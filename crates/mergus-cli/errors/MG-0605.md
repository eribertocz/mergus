# MG-0605 · The input of a history model has a key twice

- Exit code: 1
- Retryable: no
- Rules: MG-REQ-0662

## Cause
A history model (`refresh = "history"`) reads an input that is not a raw table's changes view,
and that input has the same `key` value in more than one row. Its rows then have no order to
be applied in, so the run stopped and the history table was left as it was.

## Example
the input of the history table `dim_customer` has the key `42` more than once

## Fix
Make the model's input return one row per key, for example with `QUALIFY row_number() OVER
(PARTITION BY customer_id ORDER BY updated_at DESC) = 1`, then run again.
