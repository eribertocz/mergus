# MG-0605 · A history model does not declare `key` and `by`

- Exit code: 1
- Retryable: no
- Rules: MG-REQ-0661

## Cause
A model with `refresh = "history"` keeps every version of each key, so it must declare its
business key in `key` and what detects a change in `by`: one column whose increase opens a
version, or a list of columns compared for a difference. This one lacks one or both, so the
plan cannot be built.

## Example
MG-0605: history model `dim_customer` does not declare `key` and `by`; declare the business key
and the column or columns that detect a change

## Fix
Declare `key` and `by` on the model. `deletes` is optional and defaults to `ignore`.
