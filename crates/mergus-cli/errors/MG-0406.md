# MG-0406 · Source extraction stopped after three consecutive failures

- Exit code: 1
- Retryable: no
- Rules: MG-REQ-0428

## Cause
While Mergus reads a source, it sends each chunk statement again when it fails or times out.
After three consecutive failures it stops the extraction of the source, so that Mergus is never
the reason a source database becomes slow. It does not retry until the next trigger. A slow
chunk is not a failure: it only slows the pace. The error names the source, the table being
read and the last failure.

## Example
The extraction of source `erp` stopped after 3 consecutive failures reading table `orders`;
it is not retried until the next trigger. Last failure: canceling statement due to statement
timeout.

## Fix
Check that the source, or its replica, is reachable and not overloaded. A statement that times
out may need a larger `query_timeout`, a lower `load`, or an index (`mergus doctor --source
<name>`). The next trigger reads the source again.
