# MG-0101 · A value cannot be represented exactly in its target type

- Exit code: 1
- Retryable: no
- Rules: MG-REQ-0180

## Cause
A DuckDB step reads an input whose schema declares a type for each column, and a value of a
column cannot be held exactly in that type: a decimal with more digits than the declared
precision, a decimal with more fractional digits than the declared scale, an integer beyond
the range of the declared integer type (such as a HUGEINT into BIGINT), a timestamp whose
time zone would change, or a type DuckDB has no exact equivalent for. Mergus never rounds,
truncates or casts such a value, so the step failed before its SQL ran.

## Example
input `amounts`, column `amount`: the Decimal128(12, 2) value of row 1 cannot be represented exactly as Decimal128(8, 2)

## Fix
Widen the declared type of the column, for example to a larger `DECIMAL` precision or to
`HUGEINT`, or change the step that produces the input so its values fit, then run again.
