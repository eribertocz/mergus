# MG-0702 · A column loses information at a boundary

- Exit code: 1
- Retryable: no
- Rules: MG-REQ-0720, MG-REQ-0722

## Cause
A model runs a DuckDB segment followed by a Polars segment, and a column crossing that
boundary has a type that Polars cannot hold without loss: `HUGEINT`, `UHUGEINT`, `UNION`,
`BIT`, `INTERVAL`, a `DECIMAL` with more than 38 digits, or a type the planner does not know.
The type passport gate of stage 4 checks every boundary before execution, and no step runs
while a gate blocks.

## Example
MG-0702: gate `type_passport`, model `stg_orders`, step `load`: the column `big` of type
`HUGEINT` loses information from DuckDB to Polars at the boundary from segment 0 to segment 1;
fix: cast `big` in the step `load` to a type Polars keeps, for example `VARCHAR` or
`DECIMAL(38, <scale>)`

## Fix
Cast the column in the step that outputs it to a type that crosses without loss, such as
`BIGINT`, `DECIMAL(38, <scale>)` or `VARCHAR`, or stop the Polars step from reading it.
