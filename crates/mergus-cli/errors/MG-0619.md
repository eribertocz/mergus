# MG-0619 · A step returns something that is neither literal SQL nor a LazyFrame

- Exit code: 1
- Retryable: no
- Rules: MG-REQ-0613

## Cause
The return of a step decides its engine: a string literal is SQL that DuckDB runs, and any
other expression is a Polars LazyFrame. SQL built at run time, from an f-string, a binary
operation such as `+` or `%`, `.format(...)` of a literal or a variable, cannot be checked before the run. A
step that returns `None`, has no `return`, or returns both kinds has no engine. The error names
the file, the line and the step.

## Example
`models/orders.py` line 7: step `recent` returns an f-string; return SQL as one string literal,
or a Polars LazyFrame

## Fix
Return SQL as one string literal, or return a Polars LazyFrame. Read values through the step's
inputs or the run parameters, never by building SQL text.
