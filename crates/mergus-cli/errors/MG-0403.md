# MG-0403 · Incremental table without a delete policy

- Exit code: 0
- Retryable: no
- Rules: MG-REQ-0416

## Cause
A warning: a table of a source file declares `incremental` but no `deletes`. An incremental
load reads only new and changed rows, so rows deleted in the source will not be seen and stay
in raw. The warning names the file, the line of `incremental`, the table and the source.

## Example
`sources/erp.toml` line 7: table `sales` of source `erp` is incremental but declares no
`deletes`; rows deleted in the source will not be seen.

## Fix
Declare `deletes` on the table: `column:<name>` for a soft-delete column, `compare` to compare
keys with the source, or `none` to state that deletes are ignored.
